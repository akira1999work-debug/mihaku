# テスト

> ECC testing rules をmihaku向けに統合。

## カバレッジ目標: 80%

## テスト種別（すべて必要）

1. **ユニットテスト** — 個別の関数、ユーティリティ、ロジック
2. **コンポーネントテスト** — React Nativeコンポーネントの描画・操作
3. **E2Eテスト** — クリティカルなユーザーフロー

## テスト駆動開発（TDD）

新機能・バグ修正では:
1. テストを先に書く（RED）
2. テストが失敗することを確認
3. 最小限の実装（GREEN）
4. テストがパスすることを確認
5. リファクタリング（IMPROVE）
6. カバレッジ確認（80%+）

## テスト失敗時

1. **tdd-guide** エージェントを使用
2. テストの分離を確認
3. モックの正しさを検証
4. テストではなく実装を修正する（テストが間違っている場合を除く）
