## 6. ユーザーフロー（現在）

### 初回起動
```
アプリ起動 → オンボーディング（AI対話 3〜4ターン）
→ AIがカテゴリ提案 → ユーザー確認 → メイン画面へ
```

### 日常利用
```
ホーム画面（Now Playing）
→ フォーカスタスクを確認
→ 完了 or スキップ → 次のタスクへ
→ タスク追加（テキスト入力 → AI自動カテゴリ分類）
```

### しんどい時
```
「今日は無理！」ボタン
→ 理由選択（予定変更 / 休みたい / つらい）
→ ケアモード発動（彩度低下 + 負荷軽減）
→ 自動解除 or 自己申告で解除
```

### タスクレビュー
```
タスク詳細画面 → AIレビュー実行
→ 性格診断型ラベル（ゴール直結 / デイリーケア 等）
→ 4軸評価（必要性 / 実現性 / 分解度 / 効率性）
→ サブタスク自動提案
→ 聖域判定（趣味は最適化しない）
```

## 7. 見直し作業の進め方

### Step 1: コンセプト再確認
- アプリの一言説明は何か？
- 競合との差別化ポイントは？
- MVP（最小限の機能）は何か？

### Step 2: 機能の取捨選択
- セクション3の表の「残す / 捨てる / 変更」を全て埋める
- 各機能の優先度（Must / Should / Could / Won't）を決める

### Step 3: 画面設計
- 確定した機能に基づいて画面一覧を再定義
- ワイヤーフレーム作成（紙 or Figma）
- 画面遷移図の作成

### Step 4: ビジュアルデザイン
- カラーパレット・タイポグラフィ確定
- コンポーネントデザイン
- 全画面のモックアップ

### Step 5: 開発
- 確定したデザインに基づいて実装
- TDDアプローチ（テスト先行）
