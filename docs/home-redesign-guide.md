# EdenQuest ホーム画面リデザイン — 実装ガイド

## 概要

ホーム画面のUIをCanvaデザインから実装するためのフロー。
素材は全てPNGで統一し、Vercel（next/image）の自動最適化に任せる。

---

## Phase 1: Canvaで素材書き出し

1. Canvaでホーム画面デザインを開く
2. 各パーツを1つずつ別ページにコピペ（12パーツ = 12ページ）
3. **ページサイズは全て2880x1920のまま**（個別リサイズ不要）
4. 「共有」→「ダウンロード」→ **PNG / 透過背景 / すべてのページ** で一括ダウンロード
5. ダウンロードされたファイルを作業用フォルダに配置

## Phase 2: リネーム + リサイズ

Canvaの一括ダウンロードはファイル名が `EdenQuest Home - 1.png` のような連番になる。
リネームマッピングとリサイズをスクリプトで一括処理する。

### 手順

1. ダウンロードした画像を目視確認し、番号とパーツの対応を把握
2. `scripts/rename-map-template.txt` を入力フォルダに `rename-map.txt` としてコピー
3. 番号を実際の対応に合わせて編集

```txt
# rename-map.txt の例
1 = logo
2 = pet-frame
3 = speech-bubble
...
```

4. スクリプト実行:

```bash
# 初回のみ
pip install Pillow

# 実行（プロジェクトルートから）
python scripts/resize-assets.py 入力フォルダのパス public/images/home
```

スクリプトが以下を一括処理:
- **リネーム**: 連番 → わかりやすいファイル名
- **トリミング**: 透過部分の余白を自動除去
- **リサイズ**: 各パーツに適したサイズに縮小（Retina 2x対応）

## Phase 3: v0.devでレイアウト生成

1. v0.dev にアクセス
2. 以下を添付:
   - 全体図（ホーム画面完成イメージ）
   - 個別パーツ画像（添付上限を超えたら2回に分ける）
3. プロンプトの核心:
   - **「CSSで装飾を再現するな、全て画像を `<Image>` で配置しろ」**
   - 全パーツを `/images/home/xxx.png` パスで参照させる
   - Props インターフェースを指定してクリック可能にする
4. v0.dev の出力コードをコピー保存

### v0.dev プロンプト要約

```
- Next.js App Router, Tailwind CSS v4, shadcn/ui, TypeScript
- next/image の <Image> コンポーネントで画像を配置
- ボタン・バナー・フレーム等は全て /images/home/ 配下の画像素材を使用
- CSSやSVGで模倣しない
- 横向き（landscape）レイアウト、タブレット横持ちがメインターゲット
- 全体の背景色: クリーム系 #FFF8F0
```

### v0.dev 汎用プロンプトテンプレート

> ページごとに `{...}` の部分を書き換えて使う。
> 添付画像: ① 画面の完成イメージ（全体図） ② 各パーツ画像

````

## 技術スタック（厳守）
- Next.js App Router + TypeScript
- Tailwind CSS v4
- shadcn/ui
- 画像は全て next/image の `<Image>` コンポーネントで配置

## 最重要ルール
- ボタン・フレーム・バナー・ロゴ等の装飾は **全て添付した画像素材をそのまま使え**
- CSS グラデーション、border、box-shadow、SVG 等で **素材の見た目を模倣・再現するな**
- テキスト（動的に変わる文字列）のみ CSS で描画してよい
````

## 素材形式ルール

- **全パーツPNG（透過）で統一** — SVG・WebP変換はしない
- フロー: Canva書き出し → スクリプトでリサイズ → `next/image` で配置 → Vercel自動最適化
- 将来の修正時も同じフロー: Canvaで修正 → PNG書き出し → スクリプト → 差し替え

## 却下した案と理由

| 案 | 却下理由 |
|----|---------|
| SVGとPNGの混在管理 | 管理フローが二重化する。容量差も誤差レベル |
| 自前WebP変換スクリプト | Next.js + Vercelが自動でやるため不要 |
| GitHub Actionsで画像最適化 | 同上。過剰な複雑化 |
| ボタンをCSSで実装 | カスタムイラストの忠実な再現が不可能 |
| Canva側でパーツごとにリサイズ | 手間が大きい。スクリプトで自動化した |
